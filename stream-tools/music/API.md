# Контракт воспроизведения

Модуль принадлежит пульту Ankuzo. Браузер пульта и OBS используют одну очередь и одно положение в секундах. Новая операция сохраняет прежний маршрут OBS и формат существующих полей состояния; `playerKind` добавлен в состояние администратора без удаления полей.

## Пульт

`POST /obs/music/api/preview-player` требует существующую авторизацию администратора, JSON, `X-Ankuzo-Music: 1` и тот же Origin. Тело ограничено 8192 байтами.

Тело: `{player: string, event?: {type: "progress" | "ended" | "error", id: string, epoch: number, position?: number}}`. Идентификатор плеера — случайный идентификатор вкладки, 8–80 символов `[A-Za-z0-9_-]`. `position` — секунды реального media element. `epoch` меняется после команды воспроизведения/паузы/перемотки и защищает от устаревшего подтверждения. Сервер назначает роль `preview`; роль из тела запроса не принимается.

Ответ 200: обычное полное состояние администратора с полем `owner: boolean`. Только владелец подтверждает прогресс и окончание. `playerKind` принимает `preview`, `obs` либо `null`, если активного владельца нет. Heartbeat продлевает владение на 7 секунд. Пульт отправляет его каждые 750 мс. Для закрытия: то же тело с `type: "release"`; повторное освобождение безопасно.

Ошибки: 401 без входа, 403 для ссылки зрительского виджета и неверного Origin/заголовка, 400 для неверного тела/плеера, 405 для неподдерживаемого метода изменения. Сбой сети останавливает и заглушает местный плеер; следующий успешный heartbeat восстанавливает владение и положение.

## OBS и конкуренция

Существующий `POST /obs/view/music/<token>/api/player` сохраняется. Его серверная роль — `obs`. OBS может забрать владение у пульта. Вторая вкладка пульта или второй OBS не забирают владение у такого же активного плеера. Плеер без владения не подтверждает время. Второй OBS заглушён; пульт может давать личное прослушивание через отдельное владение монитором в браузере. Местное видео синхронизируется с OBS.

При нормальном закрытии OBS пульт получает владение следующим heartbeat; после потери связи с OBS — по истечении 7 секунд и следующего heartbeat. Роль и событие проверяются сервером; зрительская ссылка не получает доступ к состоянию администратора. Личное прослушивание при этом сохраняет собственную громкость.

При открытии/передаче источника, перемотке и изменении epoch media element принимает серверную позицию после загрузки metadata. Во время самостоятельного воспроизведения пульт не возвращает видео к запаздывающему снимку состояния. При запрете autoplay появляется кнопка включения звука.

## Проверки

Регрессия должна покрывать пульт без OBS, монотонность времени, паузу/перемотку, аудио при скрытом клипе, приоритет OBS, возврат в пульт, отсутствие двойного звука во второй вкладке, автоматический следующий трек и запрет административного heartbeat по ссылке виджета. Проверки выполняются на сервере с копией очереди, без управления настоящими заказами зрителей.

## Автовоспроизведение очереди

В существующем `api/control` → `settings` добавлен boolean `autoPlay`, по умолчанию true, включая старые сохранённые настройки. Это автоматический следующий трек уже запущенной очереди. При false естественное окончание трека или ошибка текущего воспроизведения выключают `playing` и оставляют следующие готовые заказы ждать ручного `play`. Переключатель не останавливает текущий трек. Явные `play` и `skip` сохраняют обычное ручное действие. Настройка сохраняется при перезагрузке страницы и сервиса.


## Фон, очередь и личное прослушивание

Администраторский `POST api/control` дополнен `{"action":"move","id":"UUID","beforeId":null}`: только ожидающие ready/resolving заявки. `null` — конец очереди. Текущий заказ и история не меняются; устаревшая цель возвращает 400, операция целиком сохраняется одним состоянием. Вызов с тем же id и beforeId ничего не меняет.

`GET api/yandex/library` возвращает `{ok, likesCount, playlists:[{key,title,count,group}]}`; group own/saved. `GET api/yandex/search?q=...` принимает 1–120 символов и возвращает до 20 отдельных треков `{trackId,albumId,url,title,duration}`. Каталог ограничен первыми 500 доступными треками длительностью до 1800 с.

`POST api/background` принимает:

- `{action:"source",kind:"wave"|"likes"}`;
- `{action:"source",kind:"playlist",key:"OWNER:KIND"}`;
- `{action:"source",kind:"track",key:"TRACK:ALBUM"}`;
- `{action:"previous"|"next"|"stop"|"resume"}`.

Ответ — admin state; получение каталога завершается до ответа, загрузка аудио идёт асинхронно. Неизвестный/пустой источник возвращает 400 с безопасным сообщением. Поколение источника не позволяет позднему ответу заменить более новый выбор. Смена/остановка фона не прерывает текущую заявку зрителя. Каталог, очередь и позиция атомарно сохраняются в state.json v2; прежние состояния v1 автоматически дополняются значениями по умолчанию. Перезапуск ставит воспроизведение на паузу.

Admin state содержит краткий `background:{enabled,kind,title,index,total,generation,error,nextTitle}`; items по-прежнему содержит только заказы. Current может быть фоновым: `lane:"background"`; в viewer current добавлено lane, для обычных заказов `"order"`. Зрительский токен не даёт доступ к поиску/коллекции, фоновым командам или управлению очередью. Токены и URL скачивания Яндекса в ответы не включаются.

Переходы инициирует подтверждение окончания от активного плеера: фон A → все ожидающие заказы → фон B. Resolving заявка сохраняет место и приоритет. autoPlay=false останавливает и фон, и очередь на естественной границе. Фон не создаёт Twitch redemptions и не участвует в возвратах.

Настройка settings.volume теперь относится только к OBS. Личная громкость/monitor сохраняются в localStorage браузера; отдельного API нет. При OBS пульт может воспроизводить синхронизированное аудио для владельца, но не подтверждает прогресс вместо OBS. Web Locks ограничивает монитор одной вкладкой; fallback — краткая аренда localStorage. Разные браузеры/компьютеры независимы.

«Моя волна» использует rotor sessions SDK yandex-music 3.2.2. События о реальном старте, окончании и пропуске отправляются последовательно в отдельной ограниченной очереди, не задерживающей подготовку музыки. При ошибке они могут быть потеряны; это best effort, а не гарантия изменения рекомендаций. Контракт SDK: https://github.com/MarshalX/yandex-music-api/blob/main/examples/wave_radio.py
