# ANKUZO.ONLINE

Личный игровой архив Ankuzo на React 19, TypeScript и Vite. Четыре главы связаны малиновой нитью: персонаж, колода недавних игр, статистика и профили.

## Запуск и проверки

```bash
npm ci
npm run dev
npm run lint
npm test
npm run build
```

Production-сборка находится в `dist`; `npm run preview` запускает её локально.

## Интерфейс

- `index.html` — ранний SVG-экран загрузки с доступным пропуском. `src/art/introScene.js` строит детальный ASCII-портрет по единой сетке `/art/intro-portrait.json`, полученной из `/art/ankuzo-head-master.png` (около 65 КБ вместо загрузки PNG 2,1 МБ): маска и волосы используют одну сетку, символы собираются, волосы мягко движутся, вокруг проходят светящиеся нити. Canvas работает до 30 кадров/с, останавливается в скрытой вкладке и освобождается при выходе. SVG остаётся резервом при ошибке данных портрета или недоступном Canvas. `src/art/intro.js` ждёт данные, шрифты, портрет и основные изображения; минимальный показ — 4,6 секунды, выход — 0,85 секунды. Режим без анимаций и системное ограничение движения отключают эффекты и минимальное ожидание. Пропуск/Escape немедленно отменяет ожидание; предельное ожидание — 12 секунд.
- `src/art/ArtApp.tsx` — действующий интерфейс и диалоги архива/статистики.
- `src/art/art.css` — его шрифты, цвета, адаптивные состояния.
- `src/art/motion.js` — переходы по позиции обычной прокрутки.
- `src/art/quality.js` и `qualityPolicy.js` — автовыбор графики и сохранение ручного режима в `localStorage` (`ankuzo.graphics.v1`).
- `src/art/atmosphere.js` — лёгкий фон Canvas 2D среднего режима, без ауры.
- `src/art/fullScene.ts` — лениво загружаемая WebGL-сцена Three.js: карты с толщиной, освещением и обвязкой, размытый передний план, GPU-свечение силуэта, изогнутые полупрозрачные ленты энергии, мягкое свечение отдельным проходом и искры. Аура непрерывно передаётся от персонажа игровой карте, затем сопровождает её через статистику к «Обо мне», включая обратную прокрутку. В скрытой вкладке отрисовка останавливается; при смене режима освобождаются контекст, геометрия, материалы, текстуры и буферы.
- `src/art/silk.js` — нить и обвязка карт; в полном режиме отдельный слой ореола, световые импульсы и тонкие энергетические волокна идут по той же траектории. Скорость импульсов считается по длине пути; эффекты останавливаются в скрытой вкладке и освобождаются при размонтировании. При недоступном canvas используется SVG.
- `public/art` — персонаж, рубашка карт и локальные шрифты.
- `src/data` — общий загрузчик и адаптеры снимков.

Прежние `src/App.tsx`, `src/pages`, `src/components` и SCSS сохранены как предыдущая реализация; текущая точка входа их не импортирует.

Архив открывается кнопкой «Весь архив» или нажатием на игру. Поиск и фильтр PC/PS5 работают по всей коллекции. Discord и PlayStation копируют актуальное имя; Steam, FACEIT, TeamSpeak, GitHub, Twitch и история открываются по ссылкам. Старые ссылки `#games/archive` и `#about/platforms` поддерживаются. В шапке есть три уровня графики: «Без анимаций», «Анимации», «Полные эффекты», и кнопка возврата к автовыбору. В автоматическом режиме `prefers-reduced-motion` или ≤2 доступных логических процессора / ≤2 ГБ памяти выбирают статику; ≥8 процессоров и ≥8 ГБ (либо недоступная оценка памяти) разрешают полный режим. Неизвестные и средние устройства начинают с лёгкого режима. Браузер не раскрывает точную конфигурацию ПК; эти сведения не передаются на сервер.

После загрузки и пятисекундного прогрева проверяются два последовательных окна по 120 кадров. Медиана >28 мс снижает полный режим до среднего; >45 мс — средний до статичного. Разовые паузы не влияют на выбор. Скрытые вкладки, интро, открытые диалоги и изменение размера исключаются из проверки. Повышения качества туда-сюда нет; ручной выбор имеет приоритет. Если WebGL, загрузка сцены или шейдер не работают, остаются лёгкие анимации с объяснением в меню.

## Данные и обновление

Клиент читает публичные JSON из `/data`. Steam даёт библиотеку, часы и последние игры; FACEIT — статистику и известные пики ELO; Discord — профиль; PlayStation — сохранённую коллекцию и трофеи. В окне «Статистика и обновления» видны дата и состояние каждого источника. При ошибке сервиса сохраняются последние полученные данные. Снимок старше семи дней помечается как устаревший. Пустые данные не заменяются демонстрационными числами.

Музыкальный статус появляется только при наличии настоящего трека в `yandex-music.json`. Пустой снимок не считается подключённым источником музыки.

На сервере `/opt/ankuzo/deploy/update-data.sh` запускается существующим `ankuzo-update.timer` примерно каждые шесть часов. Скрипт проверяет JSON и обновляет файлы `/opt/ankuzo-data` на месте, сохраняя inode для Docker bind mounts. Ключи находятся только в `/etc/ankuzo/update.env` и не входят в сборку или Git.

## Публикация

```bash
cd /opt/ankuzo
git fetch origin main
git merge --ff-only origin/main
chmod +x deploy/update-data.sh
docker image tag ankuzo:latest ankuzo:before-redesign
docker compose -f deploy/ankuzo.yml build ankuzo
docker compose -f deploy/ankuzo.yml up -d --no-deps ankuzo
```

Контейнер доступен существующему Caddy по сети `edge` на порту 3000. Публичные снимки монтируются отдельно и не заменяются при сборке. Проверить HTTPS, здоровье контейнера и таймер обновления. Для отката пометить сохранённый образ как `ankuzo:latest` и пересоздать только `ankuzo` с `--no-deps --force-recreate`.

Всё внутри `public` доступно посетителям. Токены, приватные идентификаторы и полная история присутствия туда не помещаются. CSP и `no-referrer` сохранены. Тяжёлые неиспользуемые исходники остаются в `source-assets`.


Подробный план текущей итерации: [PLAN-refinement.md](PLAN-refinement.md). `src/art/atmosphere.js` и `fullScene.ts` отвечают за анимированный фон; `src/data/discordProfile.ts` адаптирует оформление Discord. Все сборки и проверки этой итерации выполняются на сервере.

FACEIT показан на лицевой стороне движущейся карты; в режиме без анимации доступна отдельная статичная версия этой же карты.
