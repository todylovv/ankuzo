# ANKUZO.ONLINE

Личный игровой архив Ankuzo на React 19, TypeScript и Vite. Четыре главы связаны малиновой нитью: персонаж, колода недавних игр, статистика и профили.

## Запуск и проверки

```bash
npm ci
npm run dev
npm run lint
npm test
npm run build
```

Production-сборка находится в `dist`; `npm run preview` запускает её локально.

## Интерфейс

- `src/art/ArtApp.tsx` — действующий интерфейс и диалоги архива/статистики.
- `src/art/art.css` — его шрифты, цвета, адаптивные состояния.
- `src/art/motion.js` — переходы по позиции обычной прокрутки.
- `src/art/silk.js` — нить и обвязка карт; при недоступном canvas используется SVG.
- `public/art` — персонаж, рубашка карт и локальные шрифты.
- `src/data` — общий загрузчик и адаптеры снимков.

Прежние `src/App.tsx`, `src/pages`, `src/components` и SCSS сохранены как предыдущая реализация; текущая точка входа их не импортирует.

Архив открывается кнопкой «Весь архив» или нажатием на игру. Поиск и фильтр PC/PS5 работают по всей коллекции. Discord и PlayStation копируют актуальное имя; Steam, FACEIT, TeamSpeak, GitHub, Twitch и история открываются по ссылкам. Старые ссылки `#games/archive` и `#about/platforms` поддерживаются. Анимацию можно отключить; системный `prefers-reduced-motion` учитывается автоматически.

## Данные и обновление

Клиент читает публичные JSON из `/data`. Steam даёт библиотеку, часы и последние игры; FACEIT — статистику и известные пики ELO; Discord — профиль; PlayStation — сохранённую коллекцию и трофеи. В окне «Статистика и обновления» видны дата и состояние каждого источника. При ошибке сервиса сохраняются последние полученные данные. Снимок старше семи дней помечается как устаревший. Пустые данные не заменяются демонстрационными числами.

Музыкальный статус появляется только при наличии настоящего трека в `yandex-music.json`. Пустой снимок не считается подключённым источником музыки.

На сервере `/opt/ankuzo/deploy/update-data.sh` запускается существующим `ankuzo-update.timer` примерно каждые шесть часов. Скрипт проверяет JSON и обновляет файлы `/opt/ankuzo-data` на месте, сохраняя inode для Docker bind mounts. Ключи находятся только в `/etc/ankuzo/update.env` и не входят в сборку или Git.

## Публикация

```bash
cd /opt/ankuzo
git fetch origin main
git merge --ff-only origin/main
chmod +x deploy/update-data.sh
docker image tag ankuzo:latest ankuzo:before-redesign
docker compose -f deploy/ankuzo.yml build ankuzo
docker compose -f deploy/ankuzo.yml up -d --no-deps ankuzo
```

Контейнер доступен существующему Caddy по сети `edge` на порту 3000. Публичные снимки монтируются отдельно и не заменяются при сборке. Проверить HTTPS, здоровье контейнера и таймер обновления. Для отката пометить сохранённый образ как `ankuzo:latest` и пересоздать только `ankuzo` с `--no-deps --force-recreate`.

Всё внутри `public` доступно посетителям. Токены, приватные идентификаторы и полная история присутствия туда не помещаются. CSP и `no-referrer` сохранены. Тяжёлые неиспользуемые исходники остаются в `source-assets`.
