# ANKUZO.ONLINE

Личный игровой архив на React, TypeScript и Vite. Сайт объединяет библиотеку Steam и PlayStation, FACEIT-статистику, недавние игры и персональную страницу в одной визуальной системе.

## Запуск

```bash
npm install
npm run dev
```

Проверки перед публикацией:

```bash
npm run lint
npm run build
```

## Данные

Клиент читает снимки из `public/data/*.json`. Интерфейс показывает дату и состояние каждого источника; снимок старше семи дней помечается как устаревший. Счётчик библиотеки строится из фактически отображаемого объединённого архива, поэтому страницы «Игры» и «Статистика» используют одну цифру.

Не помещайте в публичные JSON токены, email, приватные идентификаторы или полную историю присутствия. Всё внутри `public` доступно любому посетителю сайта. Перед публикацией оставляйте только поля, используемые интерфейсом.

## Структура

- `src/components` — общие визуальные и интерактивные компоненты.
- `src/pages` — страницы игр, статистики и профиля.
- `src/data` — адаптация внешних снимков к модели интерфейса.
- `public/data` — публичные статические снимки.
- `source-assets` — тяжёлые исходники, которые не должны попадать в production-сборку.

Визуальные и UX-решения зафиксированы в `DESIGN.md`.

## Безопасность публикации

В `index.html` задана базовая Content Security Policy и политика `no-referrer`. На хостинге дополнительно задайте HTTP-заголовки `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `Permissions-Policy` и `Strict-Transport-Security`; HTTP-заголовок надёжнее meta-политики и может запретить встраивание через `frame-ancestors`.

## Тяжёлые исходники

Неиспользуемая 3D-модель `22.glb` хранится в `source-assets/models`, а не в `public`, поэтому Vite не копирует её в `dist`. Если 3D-герой снова будет подключён, модель нужно оптимизировать (Draco/Meshopt) и загружать лениво.
